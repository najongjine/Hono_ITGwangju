# HWPX 문서 작성 가이드

이 문서는 `국비학원_자체웹_기획서_초안.md`를 한글 문서로 옮길 때의 작성 방식이다.

## 문서 톤

- 화려한 디자인보다 읽기 쉬운 표와 짧은 문장을 우선한다.
- 한 페이지에 너무 많은 내용을 넣지 않는다.
- 기능 설명은 “무엇을 하는 기능인지” 중심으로 작성한다.
- 개발 용어는 필요한 경우에만 쓰고, 원장이 바로 이해할 수 있는 말로 바꾼다.

## 추천 목차

1. 구축 목적
2. 구축 범위 요약
3. 사용자 유형
4. 전체 메뉴 구조
5. 핵심 기능 정의
6. 주요 업무 흐름
7. 화면 구성 초안
8. 데이터 구성
9. 개발 우선순위
10. 결정 필요 사항
11. 1차 구축 산출물

## HWPX 편집 규칙

| 항목 | 권장 방식 |
|---|---|
| 제목 | 18~20pt, 굵게 |
| 대제목 | 14~16pt, 굵게 |
| 본문 | 10~11pt |
| 표 | 회색 헤더, 얇은 테두리 |
| 강조 | 굵게만 사용 |
| 색상 | 검정/회색 중심, 강조색 1개만 |
| 페이지 | 한 페이지 한 주제 원칙 |

## 원장에게 보여줄 때의 핵심 설명

“이 문서는 디자인 시안이 아니라, 웹사이트에 어떤 메뉴와 기능이 들어가고 각 기능이 무슨 일을 하는지 정리한 문서입니다. 이 문서에서 범위를 확정하면 그다음에 화면 디자인이나 개발 순서를 정할 수 있습니다.”

## 문서화할 때 피해야 할 것

- 기능 이름만 나열하고 설명이 없는 문서
- 개발자만 이해하는 API 중심 문서
- 화면 디자인처럼 보이지만 결정할 내용이 없는 문서
- 너무 많은 색과 장식으로 읽기 어려운 문서
- “추후 협의”가 너무 많아 범위를 확정할 수 없는 문서
